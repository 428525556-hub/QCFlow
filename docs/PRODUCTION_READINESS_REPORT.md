## 六、发现的 Bug（本轮代码审查）

1. 明细数量可能超过订单数量（`inbound_quantity`/`submitted_quantity` 无上限）——数据库层
2. 出货箱号同一订单可重复登记，导致数量重复累计——数据库层
3. 订单明细接口存在「旧版字段回退重试」，会静默吞掉真实写入错误——API 层
4. 管理员邮箱硬编码在代码中，无法按环境配置——配置层
5. 仓库提交了一批过时的测试环境 SQL 补丁和部署包（`outputs/`）——仓库卫生
6. 所有图片上传直接调用 Supabase Storage，无法切换到国内 COS——架构层

## 七、已经修复的 Bug ✅

1. ✅ 正式 Schema 增加 `inbound_quantity <= quantity`、`submitted_quantity <= quantity` CHECK
2. ✅ 正式 Schema 增加 `shipment_cartons unique(order_id, carton_no)`
3. ✅ 移除订单明细接口的旧版回退重试，错误直接暴露
4. ✅ `ADMIN_EMAIL` 改为环境变量（`lib/security.ts`），未设置时回退原邮箱
5. ✅ 删除 `outputs/` 过时补丁（可从 Git 历史恢复）
6. ✅ 新增 `src/server/storage/` 独立存储适配层，4 个图片/附件模块全部切换到适配器，未来替换 COS 零改动业务页面
7. ✅ 修复 Storage 适配层引入的类型错误（错误对象规范化）

## 八、仍然存在的问题 ⚠️

1. **应用数据层仍是 Supabase**（过渡期，按任务书第九节允许）；切换到国内 PG 是下一阶段大迁移
2. 复检数量未校验「合格+不良 ≤ 原检品数量」（需要业务确认后加约束/校验）
3. 删除检品记录会级联删除复检记录（改为 set null 需业务确认）

5. 检品记录未关联订单明细外键（明细级统计靠文本匹配）
