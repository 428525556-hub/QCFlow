## 五、数据库兼容性检查（自动结论，无需人工操作）

`production_schema.sql`（21 表 / 8 函数 / 0 数据）已就绪，但**当前代码不能直接切换**，存在以下阻塞点（已记录，不执行切换）：

1. **认证体系**：代码所有 API 用 Supabase Auth JWT 校验（`supabase.auth.getUser`），正式 PG 无此机制；切换数据库必须同时替换认证层（下一阶段工作）
2. **浏览器直连**：约 30% 的查询/写入（出货、用户、开箱、附件等模块）在浏览器直连 Supabase，依赖 RLS 权限；正式 Schema 无 RLS，直接切换会失败或越权
3. **RPC 上下文**：正式库的 8 个函数改为读取 `app.user_id/user_email`（GUC），当前代码用 `supabase.rpc` 传 JWT，切换后函数会拒绝执行，需 API 层先注入用户上下文

表结构/字段层面已对齐（新增的 `updated_at`、数量 CHECK、箱号唯一约束均为兼容增量，不阻塞）。
